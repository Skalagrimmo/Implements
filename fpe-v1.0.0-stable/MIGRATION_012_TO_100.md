# Migration — FPE 0.12.0 → 1.0.0

The 1.0 promotion is intentionally contract-preserving.

```text
public methods            unchanged (10)
public error codes        unchanged (11)
projection schema         stays fpe.pixelgen_hierarchy/0.6.0
action request schema     stays fpe.action_request/0.10.0
snapshot schema           stays fpe.runtime_snapshot/0.11.0
scheduler schema          stays fpe.scheduler_state/0.11.0
authority/writeback       unchanged (read-only / false)
runtime version           0.12.0 → 1.0.0
```

A valid 0.12 checkpoint can be passed directly to `FPE.restore()`. The next `serialize()` writes `runtime_version: 1.0.0`. Valid 0.11 checkpoints remain supported through the same migration window.

Promotion parity is tested against 64 frozen semantic traces generated by the actual 0.12 runtime. The trace digest normalizes only `runtime_version`; all scheduler, hierarchy, request, handoff and snapshot behavior must remain identical.
